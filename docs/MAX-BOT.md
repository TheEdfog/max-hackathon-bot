# РезюмИТ Найм: бот первичного отбора в MAX

Основной сценарий полностью работает в личном диалоге с ботом. Веб-кабинет — дополнительный интерфейс, он не нужен для проверки бота.

## Быстрая проверка

1. Откройте бота, нажмите «Начать» или отправьте `/start`.
2. Работодатель: `/employer КОД` (значение `HIRING_EMPLOYER_CODE`), затем название компании.
3. `/newjob` → название → описание → проверка требований. Можно заменить список: один навык на строку, `+Docker` для желательного навыка. Отправьте `Публиковать`.
4. Передайте полученную ссылку коллеге. Он открывает её со своего MAX-аккаунта, даёт согласие, присылает текст вымышленного резюме и отвечает максимум на три вопроса.
5. Работодатель: `/jobs` → команда `/candidates ID` → `/view ID_ОТКЛИКА` → `/invite ID_ОТКЛИКА Текст приглашения`.
6. Кандидат получает сообщение и отвечает `/confirm ID_ОТКЛИКА`. Работодатель получает подтверждение.

Не используйте реальные персональные данные до оформления политики оператора. Разные роли проверяются с разных MAX-аккаунтов: превращать кандидата с откликами в работодателя запрещено.

## Запуск на Windows

Из корня проекта (Python 3.13):

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-hiring.lock
Copy-Item .env.hiring.example .env.hiring
```

Заполните `.env.hiring` в редакторе: `MAX_BOT_TOKEN`, случайный `HIRING_EMPLOYER_CODE`, случайный `HIRING_SECRET` (от 32 символов). Секреты не передавайте в командной строке и не публикуйте. Для генерации используйте `python -c "import secrets; print(secrets.token_urlsafe(32))"`.

```powershell
.\.venv\Scripts\python.exe -m hiring.polling --check
.\.venv\Scripts\python.exe -m hiring.polling
```

После настройки можно запускать `RUN-BOT.cmd`. Не запускайте второй экземпляр одновременно. При закрытии процесса, выключении/сне компьютера бот перестаёт отвечать. Состояния диалогов и позиция чтения сохраняются в SQLite; после перезапуска диалог продолжается.

## Docker для локального теста

После заполнения `.env.hiring`:

```sh
docker compose -f compose.hiring.yml up --build -d
docker compose -f compose.hiring.yml logs -f
```

Контейнер работает от непривилегированного пользователя, база хранится в томе. Этот compose запускает только бота, порты наружу не открывает. Не запускайте одновременно Python-процесс и контейнер с одним токеном.

## Постоянная работа

Long Polling используется **только для разработки/тестирования**. [Документация MAX](https://dev.max.ru/docs-api/methods/GET/updates) требует Webhook для production. Готов обработчик `POST /api/max/webhook` в `hiring.main:app`:

- Нужен сервер и публичный домен с доверенным HTTPS-сертификатом.
- `HIRING_ENV=production`, сильный `HIRING_SECRET`, `HIRING_EMPLOYER_CODE`, `MAX_WEBHOOK_SECRET` (от 24 символов), HTTPS `PUBLIC_URL`.
- Запуск: `uvicorn hiring.main:app --host 0.0.0.0 --port 8000 --workers 1` за reverse proxy.
- Подписать URL через [POST /subscriptions](https://dev.max.ru/docs-api/methods/POST/subscriptions), передав `secret` и типы `bot_started,message_created`; остановить polling. Существующие подписки автоматически не удаляются.
- TLS API MAX проверяется. Корневой сертификат из Госуслуг используется только HTTP-клиентом MAX; системное хранилище доверия не изменяется.
- Нужны резервные копии SQLite, мониторинг недоставленных сообщений, регламент хранения и контакты оператора. Единственный процесс доставки; горизонтальное масштабирование требует блокировки очереди и миграций.

Веб-кабинет и `/docs` можно включить вместе с webhook; основной чат-сценарий от них не зависит. Параметры из `.env.hiring` для uvicorn загрузить через `--env-file .env.hiring`.

## Команды

| Команда | Назначение |
| --- | --- |
| `/start`, `/help` | Помощь |
| `/employer КОД` | Регистрация работодателя |
| `/newjob`, `/jobs` | Создание и список вакансий |
| `/candidates ID`, `/view ID` | Отклики и факты из резюме |
| `/invite ID ТЕКСТ` | Ручное приглашение |
| `/close ID`, `/open ID` | Приём откликов |
| `/status`, `/confirm ID` | Статусы и подтверждение кандидата |
| `/withdraw ID` | Отзыв с отдельным подтверждением |
| `/privacy`, `/cancel` | Обработка данных / отмена шага |

В группе бот не обрабатывает резюме. Авторизация работодателей по коду приглашения, доступ к откликам ограничен владельцем вакансии. Уже доставленные в MAX сообщения не удаляются при отзыве отклика — бот сообщает это пользователю.

## Что делает анализ

Локальный словарь навыков из проекта Вадима находит упоминания и цитаты. Работодатель подтверждает список требований. Отсутствие упоминания — «нет сведений», а не отсутствие квалификации. До трёх уточнений собирают контекст; решение о приглашении принимает человек. Процент покрытия — доля упомянутых требований, не рейтинг или прогноз трудоустройства.

Ограничения: сложные отрицания, синонимы вне словаря и длинные составные требования требуют ручного прочтения. Оценка не подтверждает истинность резюме. LLM в новом сценарии не вызывается. В чате пока принимается текст, не PDF-вложение; PDF с текстовым слоем поддерживает только дополнительный веб-кабинет.

```sh
python -m pytest hiring_tests -q
```

23 теста: полный API-цикл, полный чат-цикл обеих ролей, разделение работодателей, согласие и отзыв, дубликаты событий, подделка/срок MAX initData, проверка PDF, ограничение вопросов и цитаты. Тесты используют только синтетические данные и не отправляют запросы в MAX. Реальный мобильный/веб-клиент MAX проверяется вручную командой.

Основа `apps/`, `core/` — предоставленный проект Вадима; новый модуль `hiring/`. Разрешение автора получено пользователем; это не заменяет формальное подтверждение условий повторного использования для организаторов. Публичная лицензия на исходный проект не предполагается.
