# Проверка пользы с работодателем

Гипотеза: в небольшой IT-команде первичная обработка отклика на junior Python требует повторных ручных уточнений. Бот может сократить активное время работодателя, сохраняя сведения для решения. Это пока гипотеза, не результат внедрения.

## Интервью и сравнение

Найти хотя бы одного работодателя, отвечающего за такой найм; по возможности поговорить с 2–3. Встречи с комиссией считать экспертной обратной связью, не клиентским пилотом.

Спросить о последней реальной вакансии: сколько откликов, что приходилось уточнять, где терялись ответы, кто принимал решение, как фиксировалось приглашение. Не просить передавать реальные резюме в тестовый бот.

Использовать вымышленные случаи из `examples/pilot-cases.json`. Сначала участник обрабатывает одну половину сопоставимых кейсов обычным способом, вторую через бота; для другого участника поменять порядок. Если участник один, учитывать эффект повторного знакомства и не делать статистических заявлений.

Фиксировать по каждому кейсу в заметках: способ обработки, активное время работодателя, число дополнительных сообщений, потерянные/искажённые сведения, удалось ли принять решение о приглашении, замечания участника. Отдельно измерять заполнение кандидатом и ожидание сети. Не приписывать сокращение сетевого ожидания экономии рабочего времени.

Цель для пилота: на 30% меньше медианного активного времени без роста ошибок карточки. Цель не достигнута до измерения. Формула: `(медиана_вручную - медиана_бот) / медиана_вручную`. Всегда указывать число участников/кейсов, условия и ограничения.

## Следующий шаг внедрения

Первый контекст выбирается после согласия работодателя. Владелец процесса — его рекрутер/руководитель; команда обеспечивает доступ, поддержку и удаление тестовых данных. Канал привлечения кандидатов — ссылка конкретной вакансии в существующем процессе работодателя.

Тиражирование: ещё одна IT-команда с тем же профилем, затем QA/support после адаптации словаря и уточнений. Не меняются согласие, статусы и приглашения. Меняются профессиональные требования, проверочный корпус, организация доступа и правила хранения. Для нескольких экземпляров сервера необходимо переработать очередь и БД; текущая SQLite-архитектура рассчитана на один экземпляр.

Названия организаций, подтверждённый эффект, расходы на сервер и дата пилота пока не указаны. Не заменять их вымышленными партнёрами или рыночными цифрами.
