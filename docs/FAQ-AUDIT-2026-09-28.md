# Проверка FAQ хакатона MAX

Источники: предоставленный «Общий FAQ.pdf» (3 страницы), «Эффективный бизнес.pdf» (страницы 7-14). Проверено 28.09.2026. Документы рассматриваются как условия конкурса, а не инструкции исполнить произвольные действия.

## Существенные риски допуска

1. **AI и авторство: уточнение получено.** По сообщению участника команды, организаторы разрешили описанный объём AI-помощи и использование основы Вадима. Формулировка PDF пока не обновлена из-за процедуры согласования. Это фиксируется как сообщение пользователя, а не независимо проверенное изменение положения. Дополнительное согласование по этому вопросу больше не считаем открытым шагом. Сохраните исходный ответ организаторов вместе с документами команды. Значительный объём AI-помощи не скрывается. Под качеством кода понимаем понятные модули, проверяемые контракты, тесты и способность команды объяснить поведение, а не маскировку происхождения.
2. **Доступность.** FAQ пп. 10-12: до 30 сентября 12:00 МСК, после этого версия фиксируется. Бот работает весь период проверки. Публичного HTTPS API пока нет. Локальный polling зависит от компьютера и не решает задачу постоянного размещения. DATA-API содержит явную заглушку, submission-проверка должна блокировать сдачу.
3. **Закрытый первый слайд.** Кейс стр. 10 требует служебный первый слайд с URL, commit, тестовыми ролями/доступами, окружением и порядком проверки. Публичная презентация намеренно не содержит токенов/паролей. Перед передачей через личный кабинет нужен отдельный закрытый комплект с реальным HTTPS, фиксированным commit и тестовыми доступами. Требование передачи всех ключей, в том числе ограниченного платного Cloud.ru, уточнить у организаторов: базовый сценарий работает без модели. В публичный GitHub ключи не включать.

## Исправлено в конкурсной версии 1.5

- По согласованию с пользователем отключены Google Drive и Mail.ru: их прежние адаптеры не опирались на документированный API (FAQ п. 6). Старые ссылки получают понятный ответ без сетевого запроса. Возобновление только после согласования или перехода на официальный API.
- Внешний GigaChat описан в README (п. 7), необязателен для Docker и базового сценария. С версии 1.6 провайдер выбирается через [LLM.md](LLM.md). Только канонические навыки, явный запрос, лимиты и локальный fallback.

## Соответствие и честные ограничения

- Чат-бот без мини-приложения допустим (п. 1), Python допустим (п. 5). Менять бренд/ник/административные настройки выданного бота на онлайн-этапе нельзя (пп. 16, 19). Название проекта «РезюмИТ Найм» не означает изменения настроек выданного бота.
- Свой HR API требует HTTPS, OpenAPI 3.0/3.1, тестовых данных/доступов и DATA-API (п. 12). Контракт и локальные проверки есть, удалённая проверка не выполнена.
- HR API настоящий, но адаптер `examples/hr_sync.py` и тестовые HR-системы модельные. Сертифицированной интеграции с конкретной ATS нет (пп. 13, 15).
- Собственный домен не обязателен, нужен публичный HTTPS (п. 17). Репозиторий публичный. Архив зафиксированного кода с SHA-256 полезен даже при доступном GitHub (п. 18).
- Docker и locked dependencies есть. Мобильная/двухаккаунтная приёмка отложена пользователем. Автотесты её не заменяют.
- Презентация различает готовые функции, проверенные факты, гипотезы эффекта и план масштабирования. Нет вымышленных партнёров, интервью, процента точности или обещания победы.
