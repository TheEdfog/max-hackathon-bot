## История: обновление 1.6.0, упрощение и настройка LLM

Основной интерфейс - MAX. Удалены отдельный веб-клиент, HTTP-вебдемо и дублирующий Dockerfile. API и polling собираются из одного Dockerfile с разными целями. Старые ссылки `/apply/{id}` открывают активную вакансию в MAX; HTTP-контракты HR и учебный `/demo` в боте сохранены. Удалённые исходники восстановимы из Git, рабочая база не очищалась.

HTTP-схемы вынесены из `main.py` в `api_models.py`; транспорт и настройки модели отделены от генерации вопросов. Доступны отключённая модель, Cloud.ru, DeepSeek и явно разрешённый OpenAI-compatible HTTPS API. Выбор модели, таймаут и лимиты задаются окружением без пересборки Docker. Ключ Cloud.ru не используется для других сервисов. Переключение провайдера не обнуляет общую квоту, кэш разделён по конфигурации и работодателю. Новый `/api/integrations/v1/tests/ai-status` показывает конфигурацию и квоту без внешнего запроса. [Настройки и ограничения](LLM.md).

329 локальных тестов прошли, четыре deprecation-предупреждения тестовых библиотек. OpenAPI содержит 47 путей и совпадает с кодом; официальный валидатор DATA-API и `pip check` прошли. В этом изменении живых LLM-запросов не было; провайдерский протокол проверялся с подменённым HTTP-транспортом. Настоящий изолированный HTTP smoke, перезапуск и восстановление SQLite backup прошли. Четыре известных локальных секрета не найдены в публикуемых файлах и достижимой текстовой истории; это не универсальный поиск неизвестных секретов.

Открытые шаги: постоянный HTTPS, закрытые тестовые доступы, удалённая проверка DATA-API, фиксация итогового commit и обновление презентации 1.5 под итоговый стенд. ## Реализовано

- Сквозной чат-сценарий: работодатель, вакансия, ручное подтверждение требований, ссылка, согласие кандидата, текст опыта, до трёх уточнений, карточка с цитатами, приглашение, подтверждение, отзыв.

- `/demo`: восемь помеченных учебных шагов для одного аккаунта; синтетика, без изменения реальных вакансий/ролей.
- Изоляция работодателей, ограничения входа, валидация webhook/JWT/MAX initData, дедупликация, транзакции изменений, очередь с ограниченными повторами. Отзыв очищает тексты отклика и связанные серверные копии.
- PDF API: отдельный ограниченный процесс без унаследованных ключей. Основной MAX-сценарий принимает текст, не вложения.
- Минимальный Docker runtime, pinned зависимости, Caddy/HTTPS-конфигурация, команды настройки webhook, диагностики, резервного копирования, тестовых аккаунтов и удалённого DATA-API прогона.

Перед сдачей зафиксировать **фактический итоговый commit `main`**, а не номер PR: `git rev-parse HEAD`. Этот же commit должен быть на сервере и в презентации. После получения домена обновление DATA-API требует новой согласованной фиксации версии до дедлайна.

## Соответствие кейсу

Повторно прочитаны страницы 7–14 предоставленного «Эффективный бизнес.pdf». Обязательная форма — работающий сценарий в MAX, исходники с фиксированной версией, README, Docker, зависимости и PDF-презентация; для своего API также HTTPS, OpenAPI, роли/тестовые данные, DATA-API.

Кнопки и собственный API сами по себе не гарантируют платформенный бонус. Продуктовая ценность и масштабирование описаны как проверяемые гипотезы в [PILOT.md](PILOT.md), без вымышленных интервью, партнёров или экономии времени.

## Что остаётся вне автоматической проверки

1. Яндекс Cloud: реальный домен/HTTPS, секреты, один webhook, отключение локального polling, backup/мониторинг; замена `api.baseUrl` и удалённый DATA-API прогон. Порядок готов в [DEPLOYMENT.md](DEPLOYMENT.md).
2. Обязательная PDF-презентация; чувствительные технические доступы нельзя публиковать в открытом GitHub.
3. Ручная проверка мобильного и веб-MAX. У команды пока один доступный аккаунт: `/demo` помогает репетиции, но настоящий обмен работодатель↔кандидат двумя аккаунтами пока не подтверждён.
4. Пользователь сообщил о согласии Вадима. Условия повторного использования, допустимость основы и срок доступности стенда команда подтверждает у организаторов; лицензию от имени Вадима не выдаём.

До согласования оператора данных — только синтетические резюме. Текущий релиз рассчитан на один экземпляр SQLite; не заявляются проверенная высоконагруженность, SLA, exactly-once доставка или промышленная готовность для реального найма.
