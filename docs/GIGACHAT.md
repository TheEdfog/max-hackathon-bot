# GigaChat для внутренних сервисов

Версия 1.5. Cloud.ru Foundation Models, OpenAI-compatible API:
`https://foundation-models.api.cloud.ru/v1/chat/completions`, модель `ai-sage/GigaChat3-10B-A1.8B`.
Это runtime-функция подготовки теста, не помощник разработки и не сервис оценки кандидатов.

## Вызов HR API

Нужен интеграционный ключ работодателя с `tests:write`.
`GET /api/integrations/v1/tests/ai-skills` возвращает допустимые навыки.
`POST /api/integrations/v1/tests/ai-draft` принимает:

```json
{"skills":["python","sql"],"level":"junior","allow_external_generation":true}
```

Разрешены 1-5 разных канонических навыков и уровни junior/middle/senior. Свободный текст, ссылки, резюме, названия компаний, имя кандидата, переписка и ответы не принимаются. После нормализации только навыки и уровень уходят в Cloud.ru. Поле согласия обязательно даже для локального fallback, чтобы поведение запроса не менялось незаметно при включении модели.

Ответ содержит `draft`, `source` (gigachat/local), `model`, `cached`, `review_required: true`, `published: false`. Человек проверяет вопросы и критерии, при необходимости правит и сохраняет через обычный `POST /tests`. Затем можно добавить тест к вакансии и использовать его в MAX. Отдельной кнопки генерации в MAX пока нет. Ответы проверяет работодатель, автоотказа и LLM-скоринга нет.

## Лимиты и отказоустойчивость

- Модель включается только через `HIRING_GIGACHAT_ENABLED=true` и `CLOUDRU_API_KEY` в локальном `.env.hiring`.
- Один внешний запрос за вызов, максимум 1000 выходных токенов, до 64 КиБ ответа. Нет повторов, перехода к другим провайдерам или автоматического платного fallback.
- В SQLite сохраняется резерв запроса до обращения к провайдеру. До 3 новых запросов на работодателя за скользящие 24 часа, до 10 на всю базу за 24 часа, до 50 за жизнь базы. Ошибки и сбои тоже расходуют резерв. Лимит общего числа запросов защищает небольшой баланс, но не является денежным биллингом провайдера. Восстановление/замена базы может сбросить учёт, поэтому оператор также задаёт лимиты в Cloud.ru.
- Один активный резерв на 2 минуты. После сбоя резерв остаётся учтённым. Кэш по работодателю, навыкам и уровню на 24 часа. Повтор того же неуспешного запроса в этот срок возвращает локальные вопросы без нового обращения.
- Сеть вне SQLite write-lock. TLS включён, endpoint фиксирован, redirect и proxy окружения запрещены. Ответ строго валидируется как тест, никогда не исполняется. Проверка формата не гарантирует профессиональную корректность, поэтому обязательна ручная проверка.
- Ошибка сети/провайдера/JSON даёт локальный шаблон и явный `source=local`. Достижение квоты даёт 429, занятый генератор 409. Ручная библиотека и весь сценарий отклика работают без модели.
- В БД хранятся только черновики профессиональных вопросов и метаданные резервов. Автоочистки нет: удалять записи квоты во время действия бюджета нельзя.

Ключ не входит в Git/Docker-контекст и не должен попадать в презентацию для публикации. Для закрытого комплекта комиссии доступы передаются отдельно по согласованному каналу. Средствам разработки этот ключ не передавать.

## Проверка

`python scripts/smoke_gigachat.py` делает не более одного реального runtime-запроса на синтетических навыках, с постоянным отдельным кэшем в `data/hiring.ai-smoke.db`. Не читает резюме, не отправляет MAX-сообщения и не печатает ключ или ответы модели. Повтор в течение 24 часов использует кэш.

Документация провайдера: [контракт API](https://cloud.ru/docs/foundation-models/ug/topics/api-ref__specs), [каталог моделей](https://cloud.ru/products/evolution-ai-factory/catalog-foundation-models). Внешний сервис не запускается в Docker. Без его ключа доступен локальный fallback.
