# Проверка MAX после переноса на VM

28 сентября 2026, один существующий аккаунт работодателя в веб-клиенте MAX. Развёрнутый код: `c2855a3e67596f0747f1786b57f3358b42e25e41`, версия 1.7.0. Это короткая эксплуатационная проверка, не полная приёмка кандидата и работодателя.

## Подтверждено

- Локальные процессы `hiring.polling` остановлены до переноса базы и регистрации webhook. Второй обработчик не запускался.
- Перед переносом создана согласованная SQLite-копия с integrity_check. SHA256 после передачи и установки в новый volume совпал. Исходная локальная база сохранена.
- Публичный HTTPS проверен извне с обычной проверкой доверия и IP в сертификате Let's Encrypt. `/health` отвечает 200 и версией 1.7.0; OpenAPI содержит 40 путей.
- Без ключа HR API отвечает 401, webhook без секрета - 403, удалённый GitHub-маршрут - 404.
- MAX `/me` и `/subscriptions` отвечают 200; зарегистрирован ровно один webhook.
- `/start` вернул меню работодателя. Кнопка «Мои вакансии» открыла список; сохранённая вакансия Junior Python-разработчика открылась с прежней ссылкой кандидата.
- Отмена закрыла незаполненный шаг создания вакансии без изменения сохранённых записей. Новых вакансий или откликов в этом smoke не публиковали.
- После резервной копии на VM контейнер API перезапущен. Health и doctor успешны; повторный `/start` снова получил ответ в веб-клиенте.
- На последней проверке очередь содержала 28 доставленных записей, без pending/failed. Контейнер API healthy, restart policy `unless-stopped`.

## Границы проверки

Автоматические мышиные клики в этом окружении попадали в соседние кнопки. Для окончательной проверки использовано нажатие Enter на кнопке, найденной по доступному имени; проверены видимый ответ и обработанная команда. Это не подтверждение работы всех сенсорных/мышиных сценариев и не мобильная приёмка.

Не проверены два независимых MAX-аккаунта, полный кандидатский сценарий в production, полный удалённый DATA-API-набор с закрытыми синтетическими ролями, восстановление после перезагрузки всей VM и будущий цикл продления сертификата. Caddy настроен на автоматическое продление с постоянным volume; порты 80/443 должны оставаться открытыми.

Runtime не использует LLM. Локальный polling не возобновлять при работающем webhook. Презентация 1.5 устарела и требует обновления под компактную версию.
