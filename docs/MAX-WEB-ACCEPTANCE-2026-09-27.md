# Приёмка в веб-клиенте MAX — 27 сентября 2026

Среда: реальный веб-клиент MAX, настоящий транспорт Bot API, локальный long polling.
Один разрешённый физический аккаунт, три виртуальные роли в отдельной SQLite-песочнице.
Все новые вакансии, резюме и приглашения вымышлены. Идентификатор аккаунта, токен,
история личных сообщений и база в репозиторий не включены.

## Подтверждено через интерфейс

- Создание вакансии, ручная проверка и исправление требований, публикация.
- Старая кнопка публикации после изменения черновика отвергается; свежая публикует вакансию.
- Настоящая ссылка `max.ru/...?...start=apply_...` открывает согласие на отклик.
- Короткий текст резюме отвергается; следующий корректный текст принимается.
- Уточнение по PostgreSQL продолжено после остановки и повторного запуска процесса.
- Кнопка «Опыта нет» для Docker корректно сохраняет отрицательный ответ.
- Карточка различает упоминание в резюме, уточнение в ответе и отсутствие опыта.
- По кнопке доступны точная цитата Python и ответ PostgreSQL без выдуманных сведений.
- Кнопка работодателя не выполняется из роли кандидата; после переключения доступ работает.
- Другой работодатель получает «Отклик не найден» для чужого отклика.
- Работодатель отправил явно тестовое приглашение; кандидат получил его и подтвердил интерес.
- Работодатель получил уведомление о подтверждении; сводка показывает один отклик
  и одного подтвердившего интерес, без оставшихся ожидающих приглашений.

## Найдено и исправлено

1. «Docker будет плюсом» ошибочно попадал в обязательные требования.
   Добавлен учёт маркера после навыка в пределах предложения и четыре регрессионных примера.
2. Пустое тело ответа на callback давало HTTP 400 `proto.payload`.
   Реальный MAX сообщил, что нужны `message` или `notification`; добавлено нейтральное
   уведомление без изменения исходного сообщения. После перезапуска новые acknowledgements
   получили статус `sent`. Регрессионный тест теперь проверяет тело реального обработчика,
   а не вручную созданную пустую запись.
3. Подсказка после публикации в песочнице теперь предлагает переключить роль,
   а не требовать второй физический аккаунт.

## Границы результата

- Автотесты: 121 passed; три предупреждения об устаревающих интерфейсах зависимостей.
- Мобильный клиент и доставка между двумя независимыми физическими аккаунтами не проверены.
- Веб-приёмка не заменяет проверку production webhook/HTTPS после развёртывания в облаке.
- Не заявляются результаты пилота с реальными работодателями, точность квалификационной
  оценки или баллы комиссии. Бот собирает сведения, решение принимает работодатель.
- Исторические неуспешные пустые callback-ответы остаются в локальной тестовой базе;
  они не переотправляются автоматически. Основная база не использовалась для тестовых ролей.
