# Приоритеты для защиты the_swarm

Это предложения, а не гарантия оценки. Основа - требования кейса, уже реализованный сценарий и текущие ограничения. Презентация здесь не создаётся.

1. **Показать один законченный процесс.** Вакансия с собственным тестом, согласие, опыт кандидата, уточнение SQL по PostgreSQL, ответы, карточка с цитатами, решение работодателя, приглашение. Важна связь каждого шага с реальной задачей, а не число кнопок.
2. **Получить измерение от работодателя.** По [PILOT.md](PILOT.md) сравнить активное время и ошибки на одинаково сложных синтетических кейсах. Сохранить число участников, порядок и замечания. Не выдавать целевые 30% за достигнутые.
3. **Показать интеграцию в существующую работу.** ATS создаёт вакансию по своему ID, читает этапы и PDF, записывает заметку с защитой от одновременной правки. Кандидат отзывает отклик - событие позволяет ATS удалить копию. Уточнить, что готов универсальный API/пример, а не сертифицированный коннектор к конкретной ATS.
4. **Объяснить границы вывода.** Упоминание PostgreSQL - косвенный признак SQL, не доказанный уровень. GitHub - публичные метаданные, не подтверждение личного вклада. Кандидат дополняет сведения; человек решает, приглашать ли его.
5. **Снять технические риски до защиты.** Зафиксированный commit с CI, публичный HTTPS, удалённый DATA-API, проверенное восстановление из backup. На демонстрации иметь синтетический сценарий и инструкцию восстановления, а не рассчитывать на случайный внешний сайт.
6. **Показать воспроизводимость тестов вакансии.** Закрытые критерии видит только работодатель, старая вакансия сохраняет свою копию даже после изменения библиотеки. Оценки моделью без проверенной методики не заявлять.
7. **Обсудить конкретное внедрение.** Один профиль вакансий небольшой IT-команды, ответственный HR, канал приглашения кандидатов и критерий успешного пилота. Стоимость назвать после выбора сервера; масштабирование с SQLite представить как следующий инженерный этап, не готовую высокую нагрузку.

До дедлайна приоритет у доступности, ясного сценария и подтверждённой пользы. Новые облачные провайдеры моделей, универсальный парсинг любых сайтов, OCR и автоматический рейтинг сейчас увеличат область непроверенного поведения. Добавлять их стоит после пилота и отдельной оценки данных/безопасности.
