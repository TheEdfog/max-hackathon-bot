# Что повышает шансы на защите

Победа не гарантируется. Больше новых функций не обязательно даст больше баллов: сейчас важнее надёжная демонстрация, фактическая проверка API, независимые отзывы и согласованная с продуктом презентация.

## Уже реализовано в этом обновлении

Из предоставленной переписки взяты **паттерны**, а не персональные ответы: короткий блок мотивации/условий/доступности, понятное завершение и передача решения человеку. Не перенесены длинная зацикленная анкета, автоматический вердикт и обязательный сбор контактов.

- Работодатель включает три организационных вопроса перед публикацией; отвечает кандидат по желанию. Уточнение зарплаты просит валюту/период и gross/net, не угадывает их.
- Видны прогресс и сохранение ответа; пауза, продолжение и просмотр вакансии не требуют нового резюме.
- Карточка работодателя отдельно показывает ожидания кандидата, без автоматической оценки мотивации и личности.
- HR API: внешние ID, ключи с минимальными правами, лента изменений, очистка после отзыва, пример адаптера, контрактные проверки DATA-API.
- Исправлены конкретные пропуски Data Engineering-терминов, найденные на реальном материале. Это не широкая валидация качества.

## Следующие действия по убыванию ценности

1. **Доступный стенд и стабильная демонстрация.** Российская VM/HTTPS, один webhook, два независимых MAX-аккаунта, мобильный и веб-клиент. Зафиксированный commit и резервная копия. Без этого новые функции не компенсируют риск недопуска.
2. **Настоящий маленький пилот с рекрутером.** 10–20 разрешённых обезличенных профилей, несколько вакансий; сравнить время подготовки карточки вручную и с ботом. Заранее определить метрики, отдельно считать ошибки и ручные исправления. Не выдавать мнения команды за независимые отзывы.
3. **Наглядный сквозной показ интеграции.** Создать вакансию через API → пройти её в MAX → прочитать отклик в отдельном тестовом HR-приёмнике → пригласить → подтвердить → показать очистку после отзыва. Адаптер есть; промышленная ATS пока не подключалась.
4. **Объяснимость и контроль человека.** Показать на защите отрицание, неизвестный навык, дословную цитату и вопрос для уточнения. Не обещать предсказание успешности сотрудника; сравнить разметку с рекрутером на отложенной выборке.
5. **Доказательство масштабирования.** До обещаний провести воспроизводимый тест на синтетике: конкуренция откликов, задержки очереди, p95, ошибки и восстановление. Текущая SQLite/один процесс — честный MVP; PostgreSQL + отдельный sender — план, не уже доказанная архитектура.
6. **Операционная готовность.** Мониторинг HTTPS и очереди, тренировка восстановления backup, контроль расходов облака и срок доступности для комиссии. Репетиция отказа внешнего сервиса без потери ответов.
7. **Артефакты сдачи.** PDF с проблемой, результатами пилота, границами AI, архитектурой, demo и ссылкой на фиксированный commit; подтверждение разрешения на основу Вадима; приватная передача проверочных доступов. Секреты не размещать в открытом репозитории.

## Только после надёжного MVP

Согласование времени интервью с часовым поясом; готовый коннектор к одной выбранной ATS; командные роли работодателя и аудит доступа; управление сроками хранения; контролируемый импорт вакансий из разрешённого API. Приоритет выбирать по запросу пилотного рекрутера, не по числу функций.

Платформенный бонус MAX нельзя заявлять только за наличие кнопок или своего API. Дополнительную MAX-возможность стоит делать лишь при подтверждённой полезности и после проверки правил комиссией; не ломать стабильный сценарий ради предполагаемого бонуса.
