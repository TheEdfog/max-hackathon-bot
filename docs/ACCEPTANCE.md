# Приёмка перед сдачей

Автоматические тесты не подтверждают визуальную работу мобильного и веб-клиента MAX. Отметки ниже заполняет человек после реального прогона; сейчас они не выполнены.

Записать: commit, дата, проверяющий, ОС/версия клиента, ссылка бота. Два разных MAX-аккаунта, только вымышленные сведения. Не фотографировать код работодателя или токен.

## Репетиция с одним аккаунтом

- [ ] `/demo` открывает учебный сценарий, в каждом шаге видна отметка о вымышленных данных.
- [ ] Пройти восемь шагов кнопками до подтверждения интереса; повторить с пропуском уточнения.
- [ ] После «Выйти из демо» сохранилась настоящая роль, вакансии/отклики не добавились.

Эти отметки подтверждают только репетицию. Сквозной обмен между двумя людьми проверяется отдельно ниже.

## Сквозной сценарий

- [ ] `/start` показывает меню. Работодатель нажимает «Я работодатель», вводит код и название вымышленной компании.
- [ ] «Новая вакансия»: Junior Python, описание с Python/PostgreSQL и желательным Docker. Проверить/изменить требования и нажать «Публиковать».
- [ ] В описании вакансии проверить гиперссылку с подписью (например, `Документация`), затем убедиться, что ссылка выглядит и открывается в веб- и мобильном MAX. Зафиксировать поддерживаемый способ форматирования и запасной вариант с обычным URL.
- [ ] Кандидат открывает полученную ссылку в личном диалоге. Отмена не создаёт отклик. После согласия отправляет текст из `examples/pilot-cases.json`.
- [ ] Бот задаёт максимум три уточнения. После отмены и открытия «Мои отклики» доступно продолжение.
- [ ] Работодатель получает уведомление. Карточка компактна, «Цитаты и ответы» и «Полное резюме» работают без ввода ID.
- [ ] Работодатель нажимает «Пригласить», вводит сообщение. Кандидат подтверждает интерес кнопкой. Работодатель получает уведомление.
- [ ] Повторное нажатие не создаёт повторный бизнес-результат.
- [ ] Кандидат отзывает отклик с подтверждением. Работодатель больше не получает карточку, ожидающие сообщения с данными отменяются.

Повторить весь сценарий отдельно в мобильном MAX и в веб-MAX. Отметить реальные задержки и отличия интерфейса, не заполнять список по коду.

## Ошибки и доступ

- [ ] Второй работодатель не видит чужую вакансию/кандидата даже по ID.
- [ ] Чужая или устаревшая кнопка даёт понятный ответ и меню.
- [ ] Закрытая вакансия не принимает новый отклик.
- [ ] MAX принимает один текстовый PDF до 5 МБ после согласия на обработку; показывает извлечённый текст для проверки и сохраняет оригинал только после подтверждения отклика. Скан, другой формат или слишком большой файл отклоняется без отправки работодателю.
- [ ] Неверный код работодателя ограничен по попыткам, `/cancel` не сбрасывает защиту.
- [ ] Перезапуск сохраняет вакансии, состояние диалога и очередь.
- [ ] Списки больше 20 записей доступны через страницы; нет молчаливого обрезания.

## Инфраструктура и пакет

- [ ] Чистая Docker-сборка в пределах лимита комиссии, реальный контейнер проходит smoke до/после рестарта.
- [ ] HTTPS доступен с другого компьютера, webhook настроен, локальный polling остановлен.
- [ ] DATA-API прошёл структурный валидатор и два удалённых сценария с cleanup.
- [ ] Сдаваемые README, OpenAPI, YAML, код и версия стенда совпадают.
- [ ] Есть обязательная PDF-презентация, приватные доступы переданы только согласованным каналом.
- [ ] Права на основу подтверждены, точное время дедлайна и срок доступности уточнены.

Не выполненный пункт записывать как ограничение/задачу, не заменять отметку обещанием.
