# Необязательный ИИ-анализ резюме

ИИ формирует для рекрутера черновую сводку опыта, отмечает даты/периоды и предлагает нейтральные уточнения. Он не выставляет баллы, не ранжирует кандидатов и не решает, кому отказать. Существующая нормализация остаётся детерминированной: «питон» распознаётся как Python, а PostgreSQL даёт только косвенный признак для SQL.

В MAX после обычной подачи кандидат получает отдельный выбор: разрешить анализ или продолжить без ИИ. Отказ не блокирует отклик. В согласии показываются оператор, модель, исполнитель, место обработки, срок и ссылка на полное уведомление. Ссылка и её версия сохраняются вместе с точным текстом согласия. Отдельное согласие можно отозвать, не удаляя сам отклик. Не используйте рабочие резюме, пока у работодателя не заполнены юридические поля и не опубликовано его актуальное уведомление.

## Настройка

1. Скопируйте `config/ai-providers.example.json` в игнорируемый Git файл `config/ai-providers.local.json`.
2. В `providers` добавьте модель как OpenAI-compatible endpoint: публичное имя, HTTPS base URL, model ID, имя переменной окружения для ключа, точные реквизиты исполнителя, место обработки и подтверждённое по договору описание хранения запроса провайдером. В JSON записывается только имя env-переменной, не сам ключ.
3. В `companies` добавьте точное название компании, которое сохранено у работодателя в MAX, и задайте provider ID, полное юридическое наименование/адрес оператора, публичный HTTPS URL уведомления, его версию и срок хранения результата у себя в днях (1-365).
4. Ключ положите в `.env.hiring` или secret manager под указанным именем. Включите `HIRING_AI_ENABLED=true`. Конфиг читается из `HIRING_AI_CONFIG_JSON`; в контейнере локальный JSON нужно смонтировать read-only через `compose.ai-api.yml` или `compose.ai-polling.yml`.

Пример модели по умолчанию: Cloud.ru Foundation Models, `ai-sage/GigaChat3-10B-A1.8B`, ключ из `CLOUDRU_API_KEY`. Cloud.ru помечает её как внутреннюю и указывает, что данные пользователя не логируются и не хранятся; всё равно проверьте актуальные условия именно своего аккаунта/договора. Адрес исполнителя намеренно оставлен пустым, поэтому provider не включится, пока оператор не заполнит реквизиты и своё публичное уведомление. Для другой компании можно добавить собственный ключ через переменную окружения и model ID; не храните ключи в JSON или репозитории. Изменение provider или текста уведомления между показом согласия и нажатием кнопки требует повторно показать условия.

Разрешены только HTTPS URL без credentials/query string, локальных адресов и перенаправлений. Провайдеры не перебираются автоматически: ошибка модели оставляет резюме в системе и помечает анализ неуспешным. Уменьшение расходов обеспечивается согласием кандидата, одним запросом на согласие, ограничением входа 12 000 символами и ответа 700 токенами. Перед передачей удаляются явные контакты; точные совпадения с именем из MAX-профиля маскируются, но это не полная анонимизация. Результат кешируется только в рамках этого отклика и автоматически удаляется по истечении `retention_days`; повторно использовать AI-разбор на другой вакансии нельзя.

Произвольный endpoint может передавать сведения за пределы РФ и хранить их по своим правилам. Компании нужно отдельно проверить договор обработки, локализацию, cross-border требования и текст согласия, если provider не является внутренней российской моделью. Настройка ключа или ссылка рекрутера сами по себе не доказывают законность обработки.

## Локальная проверка

Автотесты используют вымышленные резюме и подменяют ответ модели; они не отправляют персональные данные и не требуют API-ключа. Для live smoke-теста используйте только искусственный текст. Результат модели в карточке и HR API помечен как черновик и сопровождается точными цитатами из текста, прошедшего минимизацию.
