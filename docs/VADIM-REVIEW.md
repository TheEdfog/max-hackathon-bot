# Что взяли из РезюмИТ Вадима и что стоит развивать

Повторный разбор 28.09.2026. Источник - предоставленный локальный `cvservice_web`, пользователь сообщил о согласии автора. Это не заявление об аудите каждой строки, независимом пентесте или прочитанном полном дипломе. Полный диплом не найден; ранее были доступны ТЗ и фрагменты. Не публикуем исходные частные документы/конфигурацию.

Проверена структура `apps` (37 Python-файлов), README, сервисы и маршруты. Подробно разобраны `match_service.py`, словари/локальное извлечение `vacancy_parser_service.py`, нормализация `core/utils.py`, логика рекомендаций, формирование контекста профиля и LLM-извлечение вакансий. Генерация резюме/писем, PDF и web-маршруты просмотрены по основным входам; полная построчная проверка этих подсистем не заявляется.

## Конкретные находки

| Подсистема исходного проекта | Решение для MAX |
| --- | --- |
| Широкий словарь технологий, аналитики, управления, продаж и soft skills | Общий словарь вакансии/резюме, дополнительные формы слов; больше не отдельный короткий набор для доказательств |
| Нормализация + связанные навыки | Направленные косвенные признаки; SQL не доказывает PostgreSQL, общее управление процессами не доказывает конкретную технологию |
| `match_service.build_match_result`: evidence, must/nice, weighted total | Адаптирован в `hiring/compatibility.py`, отдельная кнопка и приватный API; без автоматического ранжирования/отказа |
| Рекомендации: «лучше описать имеющийся опыт» и «отработать навык» | В отчёте рекрутера разделяем недостающие сведения, явное отсутствие опыта и противоречие; предлагаем конкретный следующий вопрос |
| Структурированный профиль, опыт, проекты, достижения | Кандидат может дополнить импорт своим вкладом. Полный многоразовый структурированный профиль пока не перенесён |
| LLM-извлечение новых требований и локальный fallback | Бот работает локально. Семантический охват не полностью равен варианту с DeepSeek; незнакомые требования работодатель редактирует вручную |
| Адаптация резюме, cover letter, LaTeX/PDF, диалоговые правки | Не переносим автоматически: это продукт соискателя, а не необходимый шаг первичного отбора работодателя |

## Что за «модель»

Найденная модель соответствия - детерминированная формула, не обученный ML-весовой файл и не LLM-судья:

`min(1, 0.65 × exact + 0.35 × related + 0.25 × min(hits/3, 1) + 0.10 × context)`.

Среднее по обязательным и желательным требованиям считается отдельно. Если есть обе группы, итог = 75% обязательных + 25% желательных. Если группа одна, используется только она. Нет требований - `null`, а не «0% квалификации».

В исходнике exact брался из списка навыков структурированного профиля, context - из его отдельных полей опыта/проектов/сертификатов. В MAX есть плоский текст и ответы, поэтому адаптация **не обещает идентичные проценты**:

- exact: положительное прямое упоминание; related: только разрешённая направленная связь;
- hits: различные утверждения, не число повторений ключевого слова;
- context: 1 при прямом упоминании с глаголом действия, 0.5 при обычном упоминании; это простая эвристика, не доказательство проекта;
- отрицания, неопределённость и противоречия не дают баллов;
- по каждому требованию доступны слагаемые, цитаты, ответы и следующий вопрос;
- GitHub-обзор, имя, контакты, популярность аккаунта, тестовые ответы не добавляют баллы в эту формулу. Профильные задания оценивает человек отдельно.

Метод `vadim-evidence-adapted-1`. Не валидирован на репрезентативной выборке найма. Процент означает покрытие требований сведениями, не компетентность или вероятность успеха. Порядок кандидатов в боте остаётся хронологическим. GitHub-обзор не меняет статусы и результат оценки.

## Предложения после этой доработки

1. **Структурированный пример опыта.** Кандидат подтверждает «задача - личное действие - результат» для 1-2 ключевых требований. Это полезнее повторения ключевых слов и позволит меньше полагаться на эвристику context.
2. **Шаблоны интервью по семействам ролей.** Analyst/PM/sales, не только разработчики; задания и критерии хранятся в существующей библиотеке. Проверять на синтетическом корпусе и с профильным работодателем.
3. **PDF-карточка для HR.** Требования, цитаты, вопросы, ручное решение, версия метода и время. Это новый отчёт, отдельно от оригинального PDF кандидата; соблюдать отзыв и правила хранения копий.
4. **Калибровка, а не новые красивые проценты.** Разметить с рекрутером независимые случаи: прямой факт, косвенный признак, нет сведений, отрицание. Измерить ошибки извлечения и полезность уточнений, не придумывать accuracy найма.
5. **Повторное использование опыта под контролем кандидата.** Сохранённый профиль с отдельным подтверждением снимка для каждой компании. Понадобятся явные правила удаления и обновления - это ещё не реализовано.

Для текущей защиты приоритетны живой стенд, демонстрация объяснимости и проверка пользы работодателем. Лишнюю генерацию документов/писем не выдаём за реализованный рекрутинговый эффект.
