# Компактная версия 1.7.2

По решению команды из продукта удалены шесть групп дополнительных функций. Старые веб-интерфейс и экспериментальные скрипты удалены из актуальной ветки; история Git сохраняется. Рабочая база не сбрасывается.

## Что осталось

- MAX: работодатель, вакансия, подтверждение требований, ссылка отклика.
- Кандидат: согласие, опыт, до трёх уточнений навыков, пропуск, пауза, продолжение, отзыв.
- Работодатель: исходные цитаты и ответы, ручное приглашение, подтверждение интереса кандидатом.
- Короткое интервью об ожиданиях и библиотека тестов до трёх заданий с закрытыми критериями и снимком у вакансии.
- Текст и PDF: импорт публичного Яндекс Диска, приём PDF-вложения в MAX, загрузка PDF через API, выдача оригинала только своей компании с PII-правом.
- HR API: ключи с правами и отзывом, вакансии по внешнему ID, отклики, приглашения, сводка, события и синхронизация отзывов.
- Учебный `/demo`, тесты, изоляция компаний, безопасная обработка PDF/URL, очередь, Docker, HTTPS и backup.

## Сопоставление без оценки

Используется общий словарь синонимов из проекта, предоставленного Вадимом. «Питон» и Python нормализуются в один навык. PostgreSQL и SQL остаются разными требованиями, но PostgreSQL показывается для SQL как отдельный косвенный сигнал и требует уточнения. Других связей между навыками, весов, коэффициентов и рейтинга кандидатов нет. Словарь и парсер находятся в `hiring/skills.py` и `hiring/requirements_parser.py`.

Для каждого требования ищутся прямые упоминания в предложениях резюме и в ответе кандидата:

1. Нет упоминания и ответа - `unknown`, «нет сведений».
2. Найден только связанный сигнал, например PostgreSQL для SQL - `indirect`, «косвенный признак»; работодатель видит источник и может уточнить опыт.
3. Есть отрицание/неуверенность в найденном предложении либо ответ без прямого названия навыка - `review`, «нужно уточнить».
4. В остальных случаях есть прямое упоминание или точный ответ - `mentioned`, «есть упоминание».

Это поиск текста, не оценка опыта. Неоднозначное предложение рассматривается целиком: например, «Python использовал, Docker не знаю» направит упоминание Python на ручную проверку тоже. Такое консервативное поведение намеренно заменяет сложный разбор области отрицания. Исходные цитаты и ответ доступны работодателю.

При отклике локально извлекаются нормализованные имена навыков и номера предложений в резюме. Кэш сохраняется у отклика, не дублирует текст резюме и переиспользуется для карточки/уточнений и повторной подачи того же кандидата на другую вакансию. Для старых записей кэш создаётся однократно при миграции БД. При отзыве очищаются текст, отпечаток и кэш. Внешняя модель не вызывается.

Счётчики API: `total`, `mentioned`, `review`, `indirect`, `unknown`. Поля `covered`, `coverage`, `direct_covered`, `inferred`, `conflicts` удалены. Уточнения выбираются из `unknown`/`review`/`indirect`, сначала обязательные требования, максимум три.

## Удалённые интерфейсы

Удалены `/applications/{id}/compatibility`, `/github`, `/review`, `/jobs/draft-from-resume`, `/tests/ai-*` после префикса HR API. Нельзя создавать новые ключи с `applications:write`. Старый параметр списка `review_stage` отвечает 410, а не молча возвращает неотфильтрованных кандидатов. Новые клиенты используют `status` и даты.

В MAX убраны кнопки покрытия и GitHub, команды их просмотра не запускают сетевых задач. Импорт принимает только Яндекс Диск. Старые ссылки других источников получают ошибку без обращения в сеть.

Модулей LLM и генерации вопросов нет. Старые локальные ключи не удаляются с компьютера владельца, но код их не читает; при развёртывании они не копируются на сервер. Шаблоны `.env` больше не предлагают эти настройки.

Старые таблицы заметок и GitHub не уничтожаются автоматически. Минимальные ORM-описания оставлены только для удаления прежних персональных данных при отзыве отклика. Рабочие вакансии, аккаунты и ответы сохраняются.

OpenAPI и DATA-API обновляются вместе с кодом. Презентация 1.5 и исторические отчёты описывают старую функциональность и не подходят для сдачи без обновления.
