# Проверка комплекта перед сдачей

Браузерные проверки MAX приостановлены по просьбе команды. Презентацию и само облачное развёртывание эта инструкция не выполняет.

## Локально, без сообщений в MAX

Из корня проекта в Python 3.13 с `requirements-hiring-test.lock`:

```sh
python scripts/release_check.py
python -m pytest hiring_tests -q
python scripts/local_smoke.py
python scripts/check_no_local_secrets.py --history
```

`release_check` читает только исходники, Git и установленные зависимости. Не загружает `.env.hiring`, не отправляет HTTP-запросов и не меняет рабочую БД. Проверяет обязательные файлы, опасные имена отслеживаемых файлов, закреплённые версии runtime, официальный DATA-API, соответствие OpenAPI коду и `pip check`. Выводит commit и SHA-256 основных артефактов. Это не универсальный сканер секретов; отдельная команда проверяет только известные локальные значения.

`local_smoke` создаёт свою временную БД, поднимает настоящий HTTP-процесс, загружает синтетический PDF, проверяет тест вакансии, HR-операции, приглашение и отзыв. Повторяет проверку после рестарта и запуска из согласованной SQLite-копии. Тестовые API-аккаунты не связаны с MAX. Временная папка с синтетической БД и логом остаётся для диагностики, путь выводится в конце.

Контейнер проверяет GitHub Actions: build, read-only запуск, HTTP-сценарий, сохранение данных после restart, конфигурация Caddy. Зелёный результат относится к конкретному commit, не к будущему серверу.

## Когда выбран сервер и домен

1. Выполнить [DEPLOYMENT.md](DEPLOYMENT.md), не публикуя секреты. Остановить локальный polling перед включением webhook.
2. Заменить `api.baseUrl` в `DATA-API.yaml` реальным HTTPS-адресом; подготовить отдельные синтетические роли по [DATA-API.md](DATA-API.md).
3. Проверить `/health` с другого компьютера, выполнить удалённый DATA-API дважды. Локальная проверка URL проверяет только формат, не DNS/сертификат/доступность.
4. Зафиксировать изменения, дождаться CI и выполнить `python scripts/release_check.py --submission`. Код 1 - ошибка локальной проверки; код 2 - незакоммиченные изменения или адрес-заглушка; код 0 - пройдены только перечисленные проверки.
5. Передать комиссии фактический commit, URL, OpenAPI, DATA-API и презентацию. Доступы для проверки передаются отдельно от публичного репозитория. Не подставлять в презентацию commit до последних изменений манифеста.

Текущий адрес `deployment-required.invalid` намеренно блокирует submission-режим. Нельзя убрать блокировку, просто заменив его произвольным доменом: живой стенд и удалённая проверка всё равно обязательны.

## Что требует участия команды

- Выбор и оплата/активация облака, домен, срок доступности стенда.
- PDF-презентация, подтверждение условий использования основы Вадима у организаторов.
- Ручная приёмка мобильного MAX и двух независимых аккаунтов, когда команда вернётся к ней.
- Публичные ссылки Google Drive, Яндекс Диска и Mail.ru прошли живую серверную проверку 28.09.2026. Проверка кнопок/отклика в MAX с этими импортами остаётся отдельной ручной приёмкой. Mail.ru зависит от формата публичной страницы; проверять его после обновлений провайдера.
- Пилот по [PILOT.md](PILOT.md). Встреча с комиссией - экспертная обратная связь, не доказанный клиентский эффект.
