# РезюмИТ Найм

MAX-бот первичного отбора кандидатов. Команда **the_swarm**: Нармаматов Алим, Огнева Анастасия, Шадрина Милана.

[Открыть бота](https://max.ru/t781_hakaton_max_bot) · [Состояние API](https://176.108.244.193/health) · [OpenAPI](https://176.108.244.193/openapi.json)

Бот развернут на сервере и принимает сообщения через HTTPS webhook. Последняя короткая приёмка и её границы описаны в [отчёте](docs/MAX-CLOUD-ACCEPTANCE-2026-09-28.md). Независимая проверка с двумя аккаунтами и в мобильном MAX остаётся отдельным шагом.

## Сценарий

Работодатель создаёт вакансию, проверяет выделенные требования и делится ссылкой на бота. Кандидат даёт согласие, отправляет опыт текстом или PDF и отвечает максимум на три уточнения. Рекрутер видит исходные цитаты и одно из четырёх состояний: «есть упоминание», «косвенный признак», «нужно уточнить», «нет сведений». Затем он сам решает, приглашать ли кандидата; кандидат подтверждает интерес.

Сопоставление сохраняет нормализованные навыки резюме и повторно использует их при следующих откликах того же кандидата с тем же текстом: «питон» становится Python без новой обработки. PostgreSQL может дать отдельный косвенный сигнал для SQL, но не считается подтверждённым опытом и ведёт к уточнению. Все правила работают локально: GPT не вызывается и токены не расходуются. Баллов, процентов и автоматического решения о найме нет.

Для интеграций есть версионированный [HR API](docs/HR-INTEGRATION.md): публикация вакансий по внешнему ID, чтение откликов и PDF, приглашения, события и отзыв доступа. Отдельные ключи API имеют ограниченные права. Публичные и закрытые данные кандидата разделены.

## Запуск разработчиком

Нужен Python 3.13. Создайте локальный файл `.env.hiring` из `.env.hiring.example`, заполните MAX-токен и код работодателя, затем установите зависимости:

```sh
python -m venv .venv
python -m pip install -r requirements-hiring.lock
python -m hiring.polling --check
python -m hiring.polling
```

Команды polling предназначены только для локальной разработки. Не запускайте их с тем же токеном одновременно с production webhook. Конфигурацию и базу можно проверить командой `python -m hiring.doctor`.

Локальный HTTP API запускается через `docker compose up --build -d`; режим локального бота без публичного порта — `docker compose -f compose.hiring.yml up --build -d`. Оба используют один Dockerfile. Не запускайте локальный polling, пока этот токен обслуживается публичным webhook.

## Проверки

GitHub Actions выполняет тесты, сверяет OpenAPI с приложением, собирает Docker-образы и проверяет сохранение данных после перезапуска. Для локального изолированного HTTP-сценария есть одна команда: `python scripts/smoke_hiring.py --local`. Она создаёт временную базу, отдельный сервер и синтетические аккаунты; MAX-сообщений не отправляет.

Официальные материалы DATA-API хакатона находятся в `tools/data_api/`. Структуру манифеста проверяет `python tools/data_api/validate_data_api.py DATA-API.yaml`; инструкции по отдельному удалённому прогону — в [DATA-API.md](docs/DATA-API.md).
